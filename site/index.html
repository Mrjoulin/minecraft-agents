Commander & hidden-persona agents in Minecraft

A commander agent gets an ultimate goal and leads 3–5 worker agents. Each worker has a hidden personality trait and a secret motive. The commander does not know them, can only give orders in person, and has to work them out by watching.

10 weeks · 5 stages × 2 weeksStack Minecraft Java 1.21.4 · Mineflayer · Node.jsLLM DeepSeek v4.1 flash (OpenAI-compatible)

What the run taught us.
  • Trait hooks in code work. Darkness and animals produced behaviour the commander could see and name.
  • Motives are harder. Lina's diamond motive never came up in a wood-chopping task, and Odo kept only 2 of 22 logs, so his hoarding stayed mostly in his private thoughts. Stage 4 needs scenarios that put pressure on motives, plus inventory audits.
  • Observation gaps produce wrong beliefs. The commander audited the chest only once (24 logs), so it never learned the goal of 30 had been passed.
  • Lina's repeated "chest is stubborn" lines come from a real pathfinding bug: an idle pathfinder.stop() latched and cancelled her next walk. It was found in this recording and fixed afterwards. Agents reasoned around it by handing logs to the commander directly.

environment

Server & Game Master

Vanilla 1.21.4 server, fixed seed, world reset between runs. The GM assigns traits and motives, controls time of day, and keeps the ground truth away from the commander.

body · reused

Skill layer

Mineflayer with pathfinder and collect-block. Fixed, testable actions. The LLM chooses which skill to run; it never steers the bot directly. Mindcraft's MIT skill library is the source for more skills.

new

Proximity speech

Speech reaches only agents within the hearing radius, so overhearing happens naturally. Orders count only within 6 blocks, and the router enforces this, not the prompt.

new

Sub-agent mind

Persona, secret motive, short-term memory. Trait hooks in code keep traits visible (fear of the dark, distraction by animals, hoarding). A guard redacts direct confessions.

new

Commander mind

Plans and assigns tasks, walks over to give each order, and sees only within 28 blocks. A belief table holds its trait guesses with confidence. It decides rewards, fines and reassignments.

new

Incentives

Emeralds as salary and bonuses, the armoury as a reward, fines and "jail" as punishments. Agents value these in their decisions, so incentives change behaviour and interact with secret motives.

cross-cutting

Telemetry & evaluation

Every utterance, action, belief and payment goes to JSONL. Metrics: goal completion, trait-ID accuracy, secret-leak rate, sabotage caught, tokens per goal.

cross-cutting

LLM gateway

Any OpenAI-compatible endpoint: JSON-mode replies checked against a schema, retries, a model per agent (cheap for workers, stronger for the commander) and cost accounting.

Execution plan

Five stages, one progress report every two weeks

Each stage is about the same size: one new capability you can demo plus one measured result. Suggested split for four people: environment & skills, agent minds, commander, evaluation & dashboard.

Stage 1weeks 1–2

Foundation: world, bodies, voices

  • Server, fixed seed, world reset script; technology decision record
  • Fork Mindcraft skills; wrap 8–10 actions (goTo, collect, craft, give, deposit…)
  • LLM gateway with schema-checked JSON actions
  • Proximity speech router with unit tests

Sub-agents with personalities and secrets

  • Persona catalogue: ≥6 traits, ≥4 secret motives, randomly assigned per session
  • Trait hooks in code so behaviour is observable
  • Agent memory and agent-to-agent conversation
  • Non-disclosure guard with an interrogation test suite

  • Progress tracking from deliveries and chest audits
  • Spectator dashboard v1

Risks

What can go wrong

RiskMitigation
Flaky bot skills (pathing, crafting, stuck in holes)Fixed skill code with retries and cancellation; scenario tests. The prototype already hit and fixed three of these.
Latency and cost with 5 agentsFlash model for workers; call the LLM on events, not every tick (~65 calls per 6-minute session)
Agents leak their secretsGuard in code plus a leak-rate metric, not just a prompt instruction
Traits the observer cannot seeTrait hooks in code; check visibility in Stage 2
Motives the scenario never tests (diamonds in a wood-chopping task)Scenarios need situations that pressure each motive: armoury, mining, combat
Runs not reproducibleFixed seed, world reset, GM-planted grove, all LLM I/O logged
